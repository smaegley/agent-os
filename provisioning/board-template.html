Your four jobs

1 · Start work

Tell Claude what you want, or drop a file in program/projects/<project>/ with state: new. Theresa turns it into a spec. You never assign anyone — the state machine routes it.

2 · Answer when stuck

blocked means an agent hit a decision or a credential only you have. It escalates to #ops-prod and never gets guessed at. Your answer gets recorded as an ADR, not left in chat.

3 · Run what QA can't

needs-exec means Eric wrote exact commands and the pass condition before seeing results, because verifying needs production access QA deliberately lacks. Run them, paste the output back, Eric rules on it.

4 · Approve the deploy

Nothing reaches production automatically — by design, not by omission. Review the spec and Eric's verdict, then say go. This gate caught a change built on a false premise today.

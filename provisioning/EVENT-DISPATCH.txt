2. DESIGN-DETAIL VALUES  (ADR §7 left these to the implementer; chosen here, all ENV-overridable)
===============================================================================================
  POLL_INTERVAL      = 10 s     new latency floor; ADR §6 recommended ~10-15 s. Idle cost is one
                                `git ls-remote` ref query per interval, no item reads, no fetch.
  reconcile interval = 5 min    OnUnitActiveSec in the .timer. Worst-case recovery of a fully
                                missed transition and worst-case dead-watcher detection are both
                                ~one interval.
  MAX_INFLIGHT       = 2        the MAX_DISPATCH=2 cascade cap, re-expressed as a system-wide
                                in-flight cap (count of fresh running.d markers).
  AGENT_TIMEOUT      = 1800 s   confirmed against dispatch.sh L55 (unchanged).
  MARKER_TTL         = 1800 s   = AGENT_TIMEOUT. A running.d marker older than this is a crash
                                orphan (agent killed before its EXIT-trap cleanup) and is reaped by
                                the sweep, so it cannot wedge an agent's mutex forever. The batch
                                never needed this — its whole-run flock+wait cleaned up; the
                                re-scoped lock does (ADR §3, Consequences).
  HEARTBEAT_MAX_AGE  = 120 s    12x the poll interval; a live watcher heartbeats every ~10 s, so
                                age exceeds this only when the watcher is actually dead.
  RECORD_STALE       = 900 s    (WR-009/ADR-0009 §3) how long a dispatched.d record SUPPRESSES a
                                re-dispatch by the stateless sweep/cron. ~3x the reconcile interval:
                                long enough to debounce a just-dispatched item, short enough that a
                                still-routable item the sweep keeps seeing self-heals in minutes
                                instead of stalling forever. Always << RECORD_TTL_DAYS. The WATCHER
                                does NOT consult this — it gates on a real state: transition, so a
                                stale record never blocks it (see §3, "no self-trigger").
  RECORD_TTL_DAYS    = 7        dispatched.d records pruned OFF DISK after this (storage hygiene,
                                separate from RECORD_STALE which governs suppression).

State lives under MAEGLEY_STATE (default /home/steve/.local/state/maegley — where running.d
already is):  running.d/<id>  dispatched.d/<id>  watch-last-commit  watch-heartbeat
watch-health-last.

3. HOW THE GUARANTEES SURVIVE WITHOUT "RUNS"  (maps to spec §6 / ADR §2-3)
===============================================================================================
  one action at a time  -> dispatch_one takes flock on /tmp/maegley-dispatch.lock for the DECISION
                           only (not the agent run), so the watcher is never blocked behind a
                           30-min agent. Watcher, sweep, and cutover cron all serialize on it.
  per-agent mutex       -> before dispatching A, under the lock, refuse if any fresh running.d
                           marker is owned by A. Marker written under the lock; removed on
                           completion/timeout. running.d is BOTH the board's truth and the mutex,
                           so they cannot drift.
  cascade cap           -> under the lock, refuse if fresh-marker count >= MAX_INFLIGHT.
  no self-trigger       -> (WR-009/ADR-0009) split by dispatcher powers. The WATCHER is stateful:
                           it diffs the state: field between its high-water commit and the tip and
                           dispatches ONLY on a genuine transition, so an agent's own follow-up
                           commit at an unchanged state is not an event and never re-dispatches it
                           -- author-free, no record consulted. A legitimate RETURN to a routable
                           state (e.g. blocked -> qa-ready) IS a transition and dispatches even past
                           a stale record. The STATELESS sweep/cron cannot diff a transition, so
                           they keep dispatched.d/<id> as a per-item debounce -- but bounded by
                           RECORD_STALE (above), so a still-routable item self-heals instead of
                           stalling. (Pre-ADR-0009 the record keyed on destination STATE alone and
                           permanently suppressed a legitimate return -- the four-item stall of
                           2026-08-20/21; that is the defect this fixes.)
  debounce              -> watcher: several commits for one logical transition are all at/<= the
                           fetched tip, so the resulting state is evaluated once. sweep/cron: the
                           RECORD_STALE-bounded dispatched.d record debounces within its window.
  write-during-read     -> the watcher reads git OBJECTS at a fixed pushed SHA, never a live
                           working tree. Concurrent pushes only advance origin to a new tip.
  crux (origin vs local)-> the watcher keys off origin's ref (ls-remote) and reads AT the pushed
                           tip. An unpushed local edit never advances the ref, never dispatches.
  terminal states       -> route() returns "" for them (unchanged); no dispatch, no re-fire.
  no missed item        -> the reconcile sweep (5 min) re-evaluates every item and feeds the same
                           idempotent path, so anything the event path dropped is recovered.
  dead != idle          -> dispatch-health.sh, run by the sweep OUTSIDE the watcher, distinguishes
                           them and alerts fail-loud. Plus WatchdogSec/Restart=always self-heal.

Pre:  copy the two .service + one .timer from provisioning/systemd/ into /etc/systemd/system/ ,
      set User= to the current dispatch cron user (confirm with `crontab -l`), `daemon-reload`.

STAGE 0  reconcile only, prove parity of the refactor.
  - Leave the 15-min dispatch cron AS IS (it now runs the refactored dispatch.sh via substrate).
  - Do NOT enable the watcher yet.
  - Confirm the refactored dispatch.sh dispatches exactly as before (DRY_RUN=1 plan matches; a real
    off-boundary transition still routes correctly). This validates the lib-dispatch.sh extraction
    before any new moving part is introduced.

STAGE 1  shadow (watcher observes, dispatches nothing).
  - Drop-in for the watch service:  Environment=DISPATCH_SHADOW=1
      systemctl edit maegley-dispatch-watch.service   (add [Service] Environment=DISPATCH_SHADOW=1)
  - `systemctl enable --now maegley-dispatch-watch.service`
  - The cron/sweep stays the sole real dispatcher. Success = the watcher's SHADOW would-dispatch
    log lines (in log/dispatch.log) match the sweep's actual dispatches over a real window: same
    items, same route() outcomes. Zero risk — the watcher writes no markers, no records, starts no
    agent in shadow.

STAGE 2  parallel (watcher dispatches for real; cron/sweep armed as backstop).
  - Remove the DISPATCH_SHADOW drop-in; `systemctl restart maegley-dispatch-watch.service`.
  - `systemctl enable --now maegley-dispatch-reconcile.timer`.
  - KEEP the 15-min cron armed. Coexistence is safe by construction: whichever of {watcher, sweep,
    cron} wins the flock and writes the running.d marker + dispatch record first dispatches; the
    others no-op. Hold here until confident (watch log/dispatch.log; no double-dispatch; latency is
    now the poll interval, not the quarter-hour).

STAGE 3  retire cron as PRIMARY (keep the low-frequency reconcile).
  - Remove ONLY the 15-min dispatch line from crontab. The reconcile .timer (5 min) keeps the
    sweep as the backstop; the watcher is primary.
  - The cron logic never left — it is the .timer's dispatch.sh at a different frequency.

FALLBACK (tested at every stage before removing the cron, per spec §6.14):
  - Re-arm: put the 15-min dispatch cron line back (*/15 07-20 * * * .../dispatch.sh) and
    `systemctl disable --now maegley-dispatch-watch.service maegley-dispatch-reconcile.timer`.
  - One config change. The system is exactly the batch it is today. Nothing else (routing, states,
    agent boundaries, the board) was touched, so rollback harms nothing.

6. WR-014 / ADR-0011 — CREDIT-EXHAUSTION HOLD  (added on top of the above; nothing else changed)
===============================================================================================
THE DEFECT: a run that died because the 5-hour credit block was exhausted looked exactly like a
transient failure (non-zero exit in ~1s), so ADR-0009's failed-run record-clear re-armed the queue
every tick, and five suppressed items stampeded the instant the block reset. The fix: credit
exhaustion is NOT a failed attempt. One shared credit-hold gate, set by classifying the CLI's own
session-limit signal, honoured first in the guard chain, expiring at the stated reset, released
rate-limited, and loud on three surfaces. ADR-0009 is preserved for GENUINE failures — narrowed
only by subtracting the exhaustion case.

NEW SHARED STATE (under MAEGLEY_STATE, alongside running.d/ dispatched.d/ etc.):
  credit-hold        line1 = reset epoch, line2 = parsed|fallback, line3+ = the captured message.
                     "Held" == file exists AND now < reset epoch. Expiry is a timestamp compare —
                     no daemon, no timer. Lifted (loud, once) by credit_hold_gc via atomic rename.
  last-dispatch-at   epoch of the last REAL dispatch, written under $LOCK; the spacing gate reads it.

NEW DESIGN-DETAIL VALUES (ADR-0011 left these to the implementer; all ENV-overridable):
  RELEASE_SPACING   = 60 s      min seconds between real starts. 60 => at most one start (one agent's
                                fresh spend) in the first 60 s after a hold lifts (AC3). Standing (not
                                armed only post-hold): it also coordinates multiple dispatchers at all
                                times, and at tens of seconds with cap=2 + human-paced hops never bites.
  CONSERVATIVE_HOLD = 18000 s   5 h — bounded hold when exhaustion is classified but the reset time is
                                UNPARSEABLE. Never unbounded, never zero: format drift degrades SAFE.
  MAX_HOLD          = 21600 s   6 h — a *parsed* reset further out than this is a mis-parse (a 5 h block
                                never resets >6 h away); clamp to CONSERVATIVE_HOLD. In the live path
                                the reset is always <=5 h out, so a fresh legit parse never clamps.

DETECTION — THE LOAD-BEARING SUBTLETY (ADR-0011 §2/§9 "the trap"): classify the CLI's OWN terminal
signal, NEVER grep the transcript for the phrase. An agent dispatched to build or verify WR-014
emits "You've hit your session limit ..." in its transcript (the spec/ADR/work-item all quote it);
a loose grep would freeze the org on its own fix. credit_exhaustion_line() keys on two anchors that
distinguish the CLI's own error from a quote of it: (1) column-0 start, and (2) at the TAIL of the
run's own captured output (a working agent keeps emitting after any quote). Only reached on a
non-zero exit. False negative -> ADR-0009 clear-and-retry (no regression). Pin/confirm the matcher
against a REAL captured message (spec §7 q2) — the only sample this build had is the one in WR-014.

WHERE IT LIVES: guard + primitives in lib-dispatch.sh (credit_held / credit_hold_gc /
credit_exhaustion_line / parse_reset_epoch / set_credit_hold / restore_record); detection + rollback
in start_agent; the credit-held first-guard + the RELEASE_SPACING gate in dispatch_one; the loud
surfaces in dispatch.sh + watch-dispatch.sh (log), doctor.sh (ok-line, no escalation), board.sh
(board-level banner); sweep.sh skips its `claude -p` digest while held (raw-facts fallback).

FAST-FOLLOW (ADR-0011 §8): the slack-bridge conversational surface (WR-013 2b — every Steve message
is a `claude -p --resume` turn) must consume this same hold state. It is a different repo, owner, and
a UX decision, so it is split to its own work item (see program projects/slack-bridge/) — the shared
credit-hold file is the contract that item reads.

FOR ERIC (on-host, per definition-of-done; this build claims NO acceptance criterion met):
  - AC1/AC7: a forced session-limit run sets the hold, does NOT consume the attempt (record ==
    pre-attempt value), and spawns ZERO `claude -p` on the next N ticks.
  - AC6: a forced NON-credit failure still clears its record and retries next tick (ADR-0009 intact).
  - AC2: the hold's expiry equals the reset named in a REAL captured message, resolved in its zone.
  - AC3: with N>=3 routable at reset, N staggered starts (>= RELEASE_SPACING apart), not one burst.
  - AC4: doctor.sh names the hold + reset while in force, as an `ok` line that does NOT escalate.
  - AC5: the board shows the hold distinctly from blocked / hold / idle.
  - AC8 (sweep half): the daily digest degrades to the raw fact block while held — no spend, no error.
  - Confirm doctor.sh/sweep.sh can READ steve's MAEGLEY_STATE/credit-hold when they run as todd
    (both use `sudo -n cat` with a plain-read fallback); if the sudo read is denied, the doctor line
    is absent and the sweep spends its (cheap, daily) digest — a gap to close, not a spend risk.
